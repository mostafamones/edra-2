# Production app services

Import `appServices` from `./platform/services` in the React Native entry point and pass it to `<EdraApp services={appServices} … />`. The module exports one stable instance and requires no startup hydration. Expo Crypto supplies UUID v4 request and idempotency keys.

- The HTTP adapter explicitly imports `expo/fetch`, omits credentials from the native cookie jar and rejects redirects. Configure the final API origin so requests reach the API without redirects. `ApiClient` supplies the current bearer token, request headers and cancellation signal. At SDK 58.0.26, Expo sets `httpShouldHandleCookies = false` on iOS and uses `CookieJar.NO_COOKIES` on Android. React Native's built-in fetch documents limitations with credential omission. [Expo fetch](https://docs.expo.dev/versions/latest/sdk/expo/#fetch-api), [React Native networking](https://reactnative.dev/docs/network#known-issues-with-fetch-and-cookie-based-authentication).
- iOS reads and writes the exact SwiftUI `lateAfterMinutes.<sessionId>` UserDefaults key through the EdraAuth bridge. Session UUIDs are globally unique. An in-place install with the same application identifier retains the existing values. The side-by-side candidate has its own defaults.
- Android reads and writes `lateAfterMinutes.<academyId>.<sessionId>` through the synchronous SecureStore API without biometric authentication. Reads happen when the session model opens. Writes persist across app restarts. The synchronous native call can briefly block JavaScript and storage errors propagate through the store contract. [Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/).
- `expo-haptics` is pinned to SDK 58's compatible 58.0.8. Recognition uses medium impact, and success, warning and failure use the corresponding notification effects. This adapter supplies haptics only. The SwiftUI app also plays system sounds for recognition, success and failure. [Expo Haptics](https://docs.expo.dev/versions/latest/sdk/haptics/).

Rebuild both native clients to pick up the dependency and iOS bridge. Native runtime verification still needs an in-place iOS upgrade with an existing deadline, an Android process restart with saved deadlines, physical-device haptics, and HTTP requests on both platforms against a controlled endpoint that can observe bearer headers, seeded cookies, response cookies, redirects and cancellation.
