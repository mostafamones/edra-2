# Edra Instructor — React Native candidate

The React Native candidate opens the API-backed Edra instructor companion on iOS and Android. The default build installs beside the SwiftUI comparison app (`../EdraInstructor.xcodeproj`). See `../AGENTS.md` for the migration and acceptance requirements.

## Toolchain (pinned)

| | Version |
|---|---|
| Expo SDK | 58.0.26 (React Native 0.88.1, React 19.3.0, Hermes, New Architecture) |
| Native tabs/stack | react-native-screens 4.30.1 + @react-navigation/native-stack 7.21.1 |
| SwiftUI components | @expo/ui 58.0.29; Liquid Glass: expo-glass-effect 58.0.5 |
| iOS minimum | 17.0 (`expo-build-properties`; SDK 58 itself supports 16.4+) |
| Android | minSdk 24, targetSdk 36, compileSdk 37 (SDK 58 defaults) |
| Node | 22 LTS (22.18 or newer); npm with the committed `package-lock.json` |

The default iOS bundle ID and Android application ID are `com.mostafamones.edra.rn`. The candidate appears as “Edra RN” and uses the `edra-rn` scheme.

The iOS Home Screen icon uses the SwiftUI app’s original Icon Composer asset in `assets/Edra.icon`. Install a fresh native build after updating it.

`ios/` and `android/` are generated (Continuous Native Generation) and git-ignored. Change native settings in `app.config.ts` or a config plugin, never in the generated projects.

## App configuration

Set these public values in `.env.local` or export them in your shell before running Expo commands:

```dotenv
EXPO_PUBLIC_EDRA_SUPABASE_URL=https://your-project-ref.supabase.co
EXPO_PUBLIC_EDRA_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx
EXPO_PUBLIC_EDRA_API_ORIGIN=https://your-edra-api-host.example
```

Use the configured Edra development project and an API origin reachable from the device. The values are bundled into iOS plists and inlined into the Android JS bundle. Keep service-role keys and other credentials out of app configuration. An unconfigured real entry presents its setup screen.

Supabase always uses HTTPS. The iOS Debug plist has the same exact `mones.ddns.net` ATS exception as the Swift app. Set `EXPO_PUBLIC_EDRA_DEV_HTTP_HOSTS=mones.ddns.net` to use that same HTTP API host on Android Debug. Both Release builds require an HTTPS API origin. iOS configuration changes require prebuild and a fresh native install. Android public environment changes require a Metro restart or a new embedded bundle.

Expo autolinks the Apple auth and camera modules. `modules/edra-auth/ios/Shared/` holds the only copy of `AuthService.swift` and `AppConfiguration.swift`; the SwiftUI comparison app compiles the same files, so both builds share one auth implementation. The config plugin installs the camera's flash icons from `modules/edra-camera/ios/Icons/` and writes the Debug ATS exception itself, so prebuild reads nothing from the SwiftUI project. The camera plugin enables camera access, with microphone and external storage permissions excluded on Android and no microphone usage description on iOS. The Android scanner builds `expo-camera` from source so ML Kit barcode scanning is included. Android sessions use SecureStore, whose backup rules exclude encrypted session storage.

## Commands

Run everything from `mobile/react-native`.

```sh
npm ci
npm run check          # typecheck, unit tests, SDK version check, iOS+Android Hermes bundle export
```

### Dev client (Metro)

Install the Edra development client to run the app on your phone. Expo Go does not contain Edra's native modules. Build and reinstall the client when native inputs change. iOS requires macOS with Xcode 26+ and CocoaPods. Android requires JDK 17 and the Android SDK with NDK 27.1.12297006.

```sh
EDRA_APPLE_TEAM_ID=XXXXXXXXXX npm run ios   # connected iPhone (prompts for a device); generates ios/ on first run
npm run android                             # connected phone or emulator
npm run native:save -- ios                  # after installing: record the client's native fingerprint
npm start                                   # Metro for the installed dev client
```

On the first iOS build of a bundle ID, Xcode must create its development profile and register the phone. Expo CLI passes `-allowProvisioningUpdates -allowProvisioningDeviceRegistration` only when it chooses the signing team itself, so the plugin leaves the team out of the generated project. Expo then signs with the identity for `EDRA_APPLE_TEAM_ID` and writes that team into `ios/`. It uses your only identity without prompting if you have just one, or prompts if none matches. Before that first build, sign in to your Apple account in Xcode > Settings > Accounts, and keep the phone unlocked with Developer Mode enabled. If `ios/` was generated by an older checkout and the build reports `No profiles for 'com.mostafamones.edra.rn' were found`, run `npm run prebuild -- --platform ios` and build again.

`npm run ios` starts Metro after it installs the app. Later, `npm start` serves Metro on your LAN (Expo's default host, the same as `npm run start:lan`). The phone and computer must share a trusted network; see Remote Metro below. If the dev client can't find the server, enter `http://<computer-LAN-IP>:8081` manually.

Run `npm run native:check -- ios` (or `android`) before starting Metro. Exit 0 means a Metro reload is enough. Exit 2 means native inputs changed (dependencies, `app.config.ts`, config plugins, local modules), so rebuild and reinstall. JS/TS edits never need a rebuild.

### Release build (no Metro)

The JS bundle is embedded; the app runs without a development server.

```sh
EDRA_APPLE_TEAM_ID=XXXXXXXXXX npm run ios:release
npm run android:release        # signed with the debug keystore: local testing only
```

### iOS upgrade verification

Use a test iPhone with the signed-in Swift app installed and public configuration pointing to the same Supabase project. The upgrade build uses `com.mostafamones.edra` and team `39YK2DQP92` to match the Swift app's Keychain identity. Installing it replaces the Swift app on that device. This build keeps team `39YK2DQP92` in the generated project, so Expo CLI does not pass provisioning flags. If Xcode reports no matching profile, build the Swift app once with `../run.sh` on this Mac (it passes `-allowProvisioningUpdates`), then retry. Run these commands only for that upgrade test:

```sh
export EDRA_IOS_IDENTITY=upgrade EDRA_APPLE_TEAM_ID=39YK2DQP92
npm run prebuild -- --platform ios
npm run ios:release
unset EDRA_IOS_IDENTITY
npm run prebuild -- --platform ios   # restore the isolated candidate project
```

Verify that the upgrade restores the existing session and academy selection. Signing accounts, TestFlight, App Store and Play distribution are separate, owner-authorized release actions.

## Remote Metro: network safety

Metro serves source code, and its dev tools can execute code in the app. Expose it only to devices you control.

- **Android over USB (preferred):** run `adb reverse tcp:8081 tcp:8081` and `npm start -- --localhost`, then use `http://localhost:8081` in the dev client. Nothing is exposed to a network.
- **Same trusted Wi-Fi (required for iPhone):** run `npm start` (or `npm run start:lan`) and open the URL or QR code from the dev client. On WSL2, phones cannot reach the NAT address. Enable `networkingMode=mirrored` in `%UserProfile%\.wslconfig`, then allow inbound TCP 8081 only on the Windows *Private* profile and only for the LAN subnet.
- **Away from the LAN:** use a private overlay you already control, such as a tailnet: `REACT_NATIVE_PACKAGER_HOSTNAME=<tailnet-ip> npm start`, with ACLs limiting port 8081 to your devices.
- **Never** port-forward 8081 on a router, bind it to a public interface, or use `expo start --tunnel`/public tunnel services. That would publish Metro to the internet.
- iOS asks for Local Network permission the first time the dev client discovers Metro; allow it. The generated Debug plist enables `NSAllowsLocalNetworking` for Metro. Connect by IP address or `.local` name. Android debug builds allow cleartext; release builds do not.

## Device acceptance

Compare the React Native build with the SwiftUI reference on the same iPhone, OS, settings and data. Check the Academy popover and independent navigation histories, conditional Scan and Announce tabs, search, keyboard and safe areas, draft and dismiss guards, native glass, gestures, Dynamic Type and VoiceOver. On Android, verify the same workflows, platform navigation and TalkBack. Use physical devices for camera and haptics.

Known iPhone differences include the classic Academy tab and toolbar search on iOS 26.0, and a Sessions sheet search drawer that uses SwiftUI's automatic display mode without an immediate search submit (SDK 58 limits; see `src/platform/chrome/README.md`). iOS 26.1 and later use the native detached search-role tab. Native compilation, Keychain upgrade continuity and device parity require separate verification.

## App structure

- `src/App.tsx` mounts the navigation and safe-area containers and passes platform bindings into `src/app/EdraApp.tsx`.
- `src/app/` owns the signed-in shell, the account and academy lifecycle, and the Sessions and Assessments histories.
- `src/features/` contains the React Native screen bodies and their workflow models.
- `src/navigation/` and `src/platform/` provide native controls, camera and runtime services.
- `modules/` contains the local Apple modules for secure auth and camera.
