# Native API integration

The API contract is owned by [web](../../web/docs/api/README.md). Current endpoint names use snake_case; native models decode those fields rather than rename the backend contract. Product words such as Finalize and Announce do not require renaming existing publication endpoints.

## Current iOS adapter

Core/Networking/APIClient.swift uses an ephemeral URLSession without cookies, obtains a bearer token per request and retries once after forced refresh on 401. POST/PATCH take a caller-created Idempotency-Key reused for the logical action. Cancellation surfaces as `APIError.cancelled`, distinct from `.network`. Token acquisition goes through `AuthService`, which classifies the Supabase SDK's errors by type and auth-server response: a missing session or a definitive rejection (4xx with a session/refresh-token/user rejection code) is signed out; network failures, timeouts, 429, 5xx and unclassified failures are recoverable and surface as `.network` without clearing credentials; a cancelled task or an SDK `refreshDiscarded` (the stored session changed during the refresh) surfaces as `.cancelled`. Only an actual HTTP 401 triggers the single forced refresh and retry, which reuses the method, body and Idempotency-Key; a second 401 after a successful refresh is `.unauthenticated` and uses the scope-bound sign-out. 401/403 have typed handling and other failures surface the backend message where available. Callers that pass `structuredErrors: true` (assignments and attendance writes) receive `.rejected(APIFailure)` with status, code, message, request id, Retry-After and raw `details`; an undecodable 2xx body is `.rejected` with code `UNREADABLE_RESPONSE` (it may follow a committed write) and an error without a backend code keeps its status as `UNCODED_ERROR`. Other callers keep `.server(message)`. A read-only POST (code lookup) sends no Idempotency-Key. The transport is injectable so tests can complete requests in any order.

The decoder converts snake_case and parses ISO dates. Keep request CodingKeys explicit where needed. Attendance uses expected versions/revisions: conflict means review the returned/current state, not retry with invented versions.

Request ownership: cancellation is best effort; correctness comes from explicit checks after every suspension point.

- Cold-launch restoration (`AuthModel.restore`) authenticates, signs out (and clears a rejected session) or, when the auth service is unreachable or failing, keeps the credentials and shows Retry; nothing academy-scoped loads until restoration succeeds. A sign-out during a pending restoration cannot be undone by its late completion.
- `AccountScope` (Core/Auth) lives for one signed-in account and ends before sign-out clears state. Models check it before committing, and their 401 callback signs out only that scope, so a late answer from an earlier account cannot sign out or populate the next one.
- `AcademyContext` is the selected academy plus a selection epoch; A → B → A yields a new context. `AcademiesModel.isCurrent(_:)` gates academy-scoped work.
- `AcademiesModel` commits only its newest load. It keeps a still-granted current selection, then the remembered one (only if the server grants it), then the first academy; it never restores an academy from cache. Network/server failures keep the granted list (not evidence of revocation).
- `SessionsModel` and `SchedulesModel` commit only their newest load for the current context; a stale 401/403 neither signs out nor clears a newer context. An older page load cannot reset a newer load's busy state.
- On a context change the shell returns to Sessions, leaves both destination stacks and resets the start flow (retry key, picker, pending navigation). Reselecting the current academy changes nothing. `AssignmentsModel`/`WorkspaceModel`/`MarkingModel` follow the same newest-load and context checks; a voluntary academy switch with an unsaved marking draft asks Save / Discard / Keep editing before `select`.

These are source behaviors with deterministic unit tests (EdraInstructorTests/RequestOwnershipTests.swift, StartSessionTests.swift, AuthModelTests.swift, TokenRecoveryTests.swift); see the README for which checks have actually been run.

## Starting a session

"Start session" on the Sessions tab opens a picker of `GET /api/v1/academies/{id}/schedules` (title search, offset pages loaded on scroll, "Planned today" grouping only, academy time zone noted when it differs). Choosing a schedule asks for confirmation, then `POST /api/v1/academies/{id}/sessions` with one Idempotency-Key per logical start. The key is kept for that academy/schedule until acknowledged: a dropped response shows the outcome as unknown and Retry resends the same key; a different schedule is a new start. Duplicate submission is blocked while in flight. `started`, `existing` and `replayed` all refresh the live list and, if the picker is still open and the context is current, open the server-returned session; the session screen shows Ended or Archived state from the server rather than presenting a replay as newly live. A 403 revalidates academies; a 401 uses the existing sign-out flow.

## Session attendance

`SessionDetailModel` belongs to the account scope and academy selection it was opened in (`isCurrent`, A → B → A is a new owner). Only its newest sheet load commits, success or failure; stale 401/403 are ignored. A lower attendance revision with the same session lifecycle/archive state is dropped, while lifecycle changes at the same revision apply. A failed background refresh keeps the last good sheet with a "Couldn't refresh" banner, the last update time and Retry. The screen shows draft counts with the official state (Not finalized / Finalized / Corrections pending) and an entry's finalized value when it differs; added students show "Added".

Attendance writes use `structuredErrors` and one policy (`AttendanceWriteOutcome`): no response, cancellation, 429, 5xx and unreadable 2xx are uncertain, keeping the whole command (body and key) for Retry; other codes are definitive and end the command (conflicts/stale reviews refetch for deliberate review). Status changes keep one command per student; a different change for a student with an unconfirmed one is refused until it is retried or discarded. Finalize opens a review sheet that captures the revision; a newer save disables Finalize until "Review latest". "Mark rest absent" appears only for mandatory sessions, counts expected Unknown students, captures the reviewed revision and calls `POST .../attendance/unrecorded-absences` (no 500-row truncation); `409 ATTENDANCE_REVIEW_STALE` requires a new review.

Scanner attempts are immutable (`ScannerModel.Attempt`: previewed card, code, Late-after captured at Confirm, key). Uncertain outcomes retry the same attempt, also after the session ended or was archived (receipts replay). `REVIEW_REQUIRED` shows the server's current entry for manual review. A code not on the loaded roster writes nothing and offers "Find student", the explicit add-attendee search prefilled with the code. "Add attendee" (`GET`/`POST .../attendance/attendees`) searches on the server, adds only on explicit confirmation against the revision shown when chosen, and never checks the student in. A server without these endpoints answers 404 or 405 without a code, shown as needing an update. Tests: `EdraInstructorTests/AttendanceTests.swift`.

## Assignment marking (EDRA-79)

The Assessments tab lists `GET /api/v1/academies/{id}/assignments` (active and closed, offset pages loaded deliberately). A workspace loads `GET /api/v1/assignments/{id}` (structure, `actions`, `student_codes_enabled`) and `GET .../marks?filter=&search=&limit=&offset=`; search runs on the server across the cohort and resets paging and selection. Rows open a full-height marking sheet; a typed code or the camera resolves through `POST .../student-resolution` (read-only) and opens the same sheet. Saves are `PATCH .../marks` by `annual_student_record_id` with per-question `answers` (choice, explicit Blank, Written Work score, clear) or fast part `marks`, plus feedback; scores are exact hundredths sent as decimal strings. The app never derives permissions: `actions` decides marking/announcing and an unknown part kind is read-only.

One Idempotency-Key per save action, retained with its immutable body until acknowledged: a dropped, throttled or 5xx response keeps the draft locked and Retry resends the same request (also on return to the foreground). `409 MARKS_CONFLICT` keeps the attempted inputs beside `details.current`; the instructor chooses Use current work or Keep my changes, and the next Save is a new action against the latest version. Announcement is separate: one row (swipe) or selected loaded rows → review sheet (names, totals, corrections) → `POST .../results/publications` with the reviewed versions and one key. `409 PUBLICATION_REJECTED` announces nobody, lists each student's reason and refreshes the list. Camera scanning pauses during lookup and marking and ignores a handled code until it leaves view; it never calls attendance endpoints.

## Current surface and limits

The native source calls academy/session/attendance reads, startable-schedule reads, session start, check-ins, attendance changes, all-remaining absence, attendee search/add and attendance publication. It also calls the assignment reads, marks search, answer/mark saves, code resolution and result announcement above. Session end/archive/restore remain web actions in the HTTP surface; required future native operations need a backend plan, not invented endpoint names. The start and schedule endpoints exist in source; a deployed server must include them before the app can use them.

Keep backend errors, retry identity and authority aligned with OpenAPI/handlers. The source enforces owner/head_admin/admin/instructor roles (decoded as a string; the app uses server-provided permitted actions, not role checks). A 403 revalidates `/api/v1/academies`: a suspended or removed academy drops out, the app leaves its session screens and discards their retry keys, and other academies and the signed-in account are unaffected. An archived session (web-managed by Owners, Head Admins and Admins) arrives with `session.archived_at` set and all permitted actions false: the session screen shows an "Archived · not counted" banner and the scanner refuses new check-ins; unconfirmed commands stay retryable (their receipts replay) and new writes return `409 SESSION_ARCHIVED`. Returning from a session screen reloads the live list. Later product rules remain intended scope. Source inspection does not verify deployed API/schema compatibility, secure token persistence or device behavior.
