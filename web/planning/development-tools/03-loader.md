## Exact aggregate mapping

All names below are in `public` unless qualified. Existing trigger-maintained totals and identity constraints remain authoritative. Keep fixture SQL in `scripts/dev-academy/sql/`, not committed schema migrations containing demo rows. Schema migrations contain only reusable tooling support.

1. Auth accounts: use Admin `createUser` with phone, random password and `phone_confirm`; do not insert fake `auth.users` rows as the SQL tests do. `profiles` is created by the Auth trigger; set fictional names on those generated profiles only. Populate `student_profiles.level_id`, `parent_phone` and `parent_phone_verified_at` for generated students so `/learn/layout.tsx` accepts them. No OTP challenge rows are needed.
2. Academy: insert `academies` under the generated owner; use the automatically initialized `academic_years` row rather than inserting a second active year. Insert `academy_memberships` for generated staff and the real owner. Add `academy_levels` and `academy_tracks` before groups and student placement. Do not modify the global catalog.
3. Students: create `academy_student_profiles`, then `annual_student_records` with academy/year/profile/name/contact/level/track/group/participation/creator. Insert the generated account link and `linked_at` as part of synthetic-profile creation, before its identity becomes immutable; do not reassign an existing account link. Use exactly one current-year annual record per student; do not generate prior-year participation.
4. Schedules: insert four recurring `schedules` in the current year, with `audience='group'`, the year's compatible group ID, null schedule-level level/track, valid `starts_on`/`ends_on`, location and generated staff creator. Insert two `schedule_slots` per schedule with the configured weekdays and non-overlapping 90-minute periods. No `schedule_sessions` rows are needed for this recurring-only fixture. Never insert upcoming `sessions` to simulate a calendar; upcoming activity is derived from schedules.
5. Historical sessions: insert fully formed ended `sessions`, including academy/year/schedule, start key, historical start/end, starter/ender identities and name snapshots, `state='ended'`, `end_reason='manual'`, `auto_end_at` at least start + 90 minutes, and group/level/track/mandatory/location snapshots. Insert five `session_roster_entries` per session, `origin='expected'`, preserving that annual record's placement and historical `created_at`. Do not update identity/snapshot fields after insertion.
6. Attendance: create one `attendance_sheets` row per session; one `attendance_publications` row with sequence 1, kind `initial`, revision 1, item count 5 and a historical staff publication time; five `attendance_records` with status/version/source/actor and matching `published_status`, publication ID and time; five matching `attendance_publication_items` with null previous status. Set sheet revision/published revision 1, publication count 1 and last publisher/time. Insert the publication before records that reference it. Use manual recording (`source='manual'`), with null check-in pairs; do not invent scans. Synthetic absence/access effects retain source identity but are explicitly suppressed, never falsely delivered.
7. Assignments: insert `assignments` with `audience='groups'`, null level/track and initial state `active`; then `assignment_audience_groups`; two typed Written Work parts (`kind='file_upload'`), each with one `assignment_part_questions` row worth 50. Physical work does not require a file. Let question/part triggers calculate totals. Insert cohort revision 1 in `assignment_cohorts` with `source='first_audience'`, historical capture time/actor and `audience_basis=edra_private.assignment_audience_basis(assignment)`; insert five `assignment_cohort_members` and five `assignment_recipients`, and set parent cohort revision/recipient count. No placement changes/endings are seeded.
8. Assignment work: received rows use `work_status='submitted'` or `late`, explicit `received_at`, recording actor/time and matching version; missing work stays `expected` without a received time. Use two `assignment_marks` with kind `mark`, scores within 0–50, no reason, `requires_remark=false`, and historical grader/time. Received-but-unmarked rows have no marks. Private fully marked rows keep `published_revision=0`. For announced rows, insert revision-1 `assignment_result_publications` with ordered part snapshots, total=sum(part scores), max=100, work status, feedback, scoring revision 1 and historical publisher/time; prior fields null. Compute the hash using **Postgres** `md5(edra_private.assignment_result_content(assignment_id, record_id)::text)`, not JavaScript JSON serialization. Mirror the snapshot shape in `20261019172557_assignment_scoring_corrections.sql` lines around its publication insert. Set recipient published revision 1. Close historical assignments only after their setup/work has been inserted, using their historical closed actor/time. Legacy assignment `published_at/by` stays null.
9. Historical exams: use one `written_work` part, five questions worth 20 each, no choices or media. Insert complete authoring while exam activity/structure locks are null; question triggers compute total/count. Availability uses opens < scheduled close and actual close = scheduled close + 2 minutes, with historical availability actor/time. Group targeting uses `exam_audience_groups`. Insert `exam_work` with no accepted source yet, and `exam_physical_drafts` with the grading staff/time. After authoring all questions, set the new fixture exam's work_started_at/structure_locked_at to the first historical received-work time before acceptance; the existing activity helper then preserves these already-set values. Accept paper work through the existing owner-only helper `edra_private.accept_exam_submission(exam, record, 'physical', 'physical', historical_received_at, historical_processed_at)` using transaction-local actor context; this creates `exam_submissions` and the accepted pointer under existing guards. Written paper work can remain untranscribed, so no invented online attempt, departure or online answer rows are necessary. Insert five `exam_marks`, then call `edra_private.announce_exam_result(exam, record, false, historical_published_at)` for published rows. This helper computes canonical result items/hash, updates published revision and refreshes solution qualification. It takes a historical timestamp explicitly. Missing work has no accepted submission or published result. Finalize/insert the historical closure record with the genuine close time. Do not overwrite protected snapshots afterward. Do not reuse helpers outside the privileged CLI fixture transaction.
10. Current exams: use `question_sheet`, five text questions worth 20 and four choices per question, one correct each. Leave work/structure locks unset and create no attempt/work/submission for the current open/upcoming exam. The real browser flow creates those. No `content_assessments` link is created.
11. Effects: add a private synthetic-effect suppression ledger keyed by run, source table and effect ID, with reason `synthetic_data`. Cover fixture effects and effects created later by ordinary preview actions through narrowly scoped insert triggers that are a no-op for non-synthetic academies. Existing attendance effect claiming must exclude the synthetic suppression ledger. Document the same exclusion for future assessment/message consumers. Do not set `processed_at` to suggest a provider send or access grant occurred.

All histories must be internally chronological; student enrollment/group creation precedes their activity. Application timestamps maintained unconditionally by existing update triggers may reflect fixture import time; retain the intended event times in their actual event fields rather than disabling those triggers. Stable logical IDs in the deterministic scenario are mapped to run-scoped UUIDs, so they never collide with another academy.
