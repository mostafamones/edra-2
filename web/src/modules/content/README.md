# Staff content workspace

`/<academy>/content` is the searchable content library and program picker. Programs inherit the academy's existing academic year, level and optional track; a unit never asks staff to configure them again. `/<academy>/content/<unit>` edits a unit. `/<academy>/releases` opens the same workspace filtered to published lessons; the In review filter surfaces submitted drafts.

## Authority and history

All operations use verified cookie authority and live academy membership. Reads retain RLS. Authenticated callers have no direct write grants on content tables. Transactional RPCs enforce ownership, manager powers, open years, optimistic versions, attachment compatibility and source provenance. The database—not disabled controls—decides permission.

Instructors edit their own never-published drafts, including while in review. Managers review, give feedback/request changes, publish and edit published units. Published documents are immutable snapshots in `content_revisions`; editing the working draft does not alter them. Archive removes active visibility; manager restoration returns to draft and keeps prior publications. Previously published restored units remain manager-editable; expanding instructor rights after restoration is not part of this implementation.

## Material and copying

The editor supports ordered explanation videos, documents, existing or newly created assignments/quizzes/exams, and answer videos attached to assessments. New assessments are created and attached atomically using the unit's program/year, then completed in the existing assessment editor. These are fresh incomplete assessment preparations, not ready/published assessments.

The existing-assessment picker is unit-scoped. Its paginated database command reuses the save/publication compatibility checker, including complete group audience coverage, academy/year, grade/optional track, archival and the one-unit attachment rule. Already attached assessments and unsaved selections are excluded. Creating directly inside the unit remains available when no compatible standalone assessment exists. The final save still revalidates because eligibility can change concurrently.

The additive picker migration is applied to development. New SQL suite runs use disposable CI databases. The signed-in development unit renders the compatible-options empty state correctly. Production build/TypeScript and all 471 regular tests pass (one opt-in provider test skipped); lint has zero errors and the ten existing unrelated warnings.

Whole-unit copying and individual-material reuse consume the last published source snapshot within the same academy. Copies are independent; media binaries can be referenced without uploading duplicates. Fresh assessment definitions are created through existing domain RPCs; structural IDs, dates, source groups, student answers, marks, results, progress and access are not carried over. The default copied audience is the whole destination program. Answer-video reuse also creates its associated assessment. Assessment locks and one-unit attachment rules remain active. Unpublished or archived source units are not offered for copying.

## Media

Videos upload from the browser directly to Mux through a server-authorized upload URL, with signed-only playback policy. Files never pass through a Next.js server action. The provider adapter is `src/lib/video/mux.ts`. Staff previews require current membership and short-lived RS256 playback tokens. The official Mux player renders playback; this is access control, not DRM.

`content_assets` tracks uploading/processing/ready/failed state. The editor polls pending uploads and verifies their current provider state server-side. An optional `/api/webhooks/mux` handler authenticates the raw body using `MUX_WEBHOOK_SECRET`, checks timestamp tolerance and synchronizes via provider IDs. A webhook endpoint has not been registered automatically because a reachable development deployment URL was not supplied. Polling does not depend on a webhook.

Upload registration is durable separately from the unit document. The editor's Uploaded files section lists this unit's registered files that are not attached to the current draft, including uploads completed before leaving without saving. Staff can preview/check and attach an existing upload as an explanation, document or assessment answer without creating another provider upload. Recovery only reads existing unit-scoped, RLS-protected asset metadata; it never auto-publishes, overwrites unsaved edits or deletes provider assets. Leaving during an active upload also triggers the browser's unsaved-work warning.

Unused videos also have a confirmed **Delete permanently** action. Save any draft removal first. The server checks live editing authority and rejects deletion if any saved unit or publication revision references the asset, including archived history and copies. A database reservation and shared reference locks block racing attachment/publication. The server cancels waiting Mux uploads or deletes their resulting assets before removing the Edra asset row. Failures preserve a retryable reservation, and provider 404/204 responses make retries safe. Pending deletion blocks preview, reattachment and provider-state synchronization. This permanently removes unused video content; Mux may retain cancelled-upload metadata, which has no video storage. Document deletion and purging published academic history are outside this action.

The explicit opt-in Mux integration test cancelled its disposable upload and deleted its disposable test video, verified provider 404 afterward and idempotent retry, and left no test videos stored. Documents use the private `content-documents` bucket, with a 25 MB database Storage limit and an allowlist for PDFs, common Word/PowerPoint documents and images. The backend marks a document ready only after its object exists. Staff receive short-lived signed document URLs. No public bucket or general client delete/update policy is created.

Server configuration: `MUX_TOKEN_ID`, `MUX_TOKEN_SECRET`, `MUX_SIGNING_KEY_ID`, `MUX_SIGNING_PRIVATE_KEY` (base64 PEM), and `SUPABASE_SERVICE_ROLE_KEY` for trusted provider-state synchronization. `MUX_WEBHOOK_SECRET` is needed only when configuring callbacks. Credentials stay in ignored local/deployment secrets, without `NEXT_PUBLIC_` prefixes. Privileged state writes happen only after staff authorization or verified provider callbacks.

## Boundaries and verification

This delivers the staff content slice. It does not implement student account/enrollment authority, learning grants, student playback/progress, DRM, watermarking, simultaneous-session policy, notifications, or session-to-content access effects. Do not expose the staff preview action to students; EDRA-139 and the access/playback issues retain those integrations.

`supabase/tests/content.sql` runs on the disposable GitHub Actions database and rolls every fixture back. It covers draft ownership, cross-academy isolation, stale saves, manager-only lifecycle, publication readiness/snapshots, restoration, fresh assessment copies and answer-video relationships. Vitest covers document validation/ownership and webhook signatures. Provider credentials and signing-key setup are separate from evidence of real browser uploads; report those checks distinctly.
