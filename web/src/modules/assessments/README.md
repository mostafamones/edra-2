# Staff Assessments list

`/app/assessments` (public `/<slug>/assessments` on the staff host) is the one staff list of assignments, quizzes and exams. Product rules: [Staff Assessments area](../../../docs/product/domains/assessments.md#staff-assessments-area). This module owns discovery, a limited quick-edit interface and a read-only assessment summary. Authoring and availability mutations, submission, marking and results stay in `assignments`, `quizzes` and `exams`; quick edit uses their public, versioned actions, and each item opens its existing `/app/<assignments|quizzes|exams>/<id>` workspace.

## Data

`list_assessments` (migrations `20261029120000_list_assessments.sql`, `20261029130000_list_assessment_counts.sql`, `20261029140000_list_assessment_program_audience.sql`, `20261029150000_list_assessment_parts.sql`, `20261029160000_list_assessment_view_options.sql`, `20261029170000_list_assessment_status_groups.sql` and `20261029180000_list_assessment_audience_filters.sql`) is a read-only security definer RPC with the same authority as `list_quizzes`/`list_exams` and the assignments RLS policy (`is_academy_member`); other or signed-out callers get `null`, which the client treats as a failure. It returns one page of a single `UNION ALL` order, so totals and pages are correct across types:

- Filters: types (any non-empty subset), academic year (or all), title search (case-insensitive substring), audience category (`program` = program-wide, covering whole-level and level-and-track audiences; `groups`; `level` alone is still accepted), level (program audiences of that level, or group audiences with a group in it), track and audience group, and shown statuses as `type:status` keys (`assignment:closed`, `quiz:closed`, …), so one type's status never selects another's. Any subset is allowed, including none.
- Order: optional grouping first (`type`: assignments, quizzes, exams; `status`: one group per status word across every type, in the order preparing, ready, scheduled, open, finishing, active, closed, archived; each item keeps its own type's status), then `newest` (created first, then type, then ID) or `title` (case-insensitive, then created, type, ID). Grouping happens in the database, so groups stay contiguous across pages.
- Row: type, ID, title, year, audience fields and group IDs, native status (assignment state or quiz/exam phase, never mapped onto each other), due date (assignments), scheduled window (quizzes/exams), `processing_pending` for quizzes/exams, the maximum the per-type pages show (assignment `max_score`; quiz/exam total of non-excluded questions), each part's title and kind in order (`parts`; a null assignment kind is a legacy marks-only part), and `marked_count` / `audience_count` with the workspace stat meanings: assignments count recipients with every part marked of the active required cohort plus optional eligible students; quizzes and exams count accepted work with a complete result of the currently eligible students.

`queries.ts` parses the page with a discriminated union; an unknown type or a status from another type fails the whole page instead of showing a partial list. The list query has `staleTime: 0`, so edits made in workspaces show when the list reopens. A failed refresh of the same request keeps the cached rows under a "Couldn’t refresh" alert; a failure after a filter change shows no rows.

SQL coverage: `supabase/tests/assessment_list.sql` (registered in `scripts/db-test.sh`): grants, mixed ordering, totals, paging, every filter, archived phase, title order, validation, cross-academy and signed-out denial.

## State

- URL (`params.ts`, `use-params.ts`): `type`, `q`, `audience`, `level`, `track`, `groupId`, `statuses` (comma list of type:status keys; omitted means everything but archived, empty means none), `sort=title`, `group=type|status`, `pageSize` (12, 24, 48 or 96; default 24), `page` (one-based). Invalid values fall back to defaults; any change except paging returns to page 1; switching type keeps the other filters. There is no year filter: the list always uses the active year (every year only if none is open).
- View (`view.ts`): Table or Cards, stored per signed-in user in `localStorage` (`edra:assessments-view:<userId>`), with an in-memory fallback when storage is blocked. Without a saved choice, Cards below the shared `useIsMobile` breakpoint (768 px) and Table otherwise; the server and hydration render use Table. Resizing never writes a choice. Switching views does not touch the URL or refetch.
- Return: the list remembers its query per tab and academy (`components/shared/assessment/list/return.ts`). Workspace and form breadcrumbs, the not-found state and cancelling a new form return to that state when it covered the item's type, otherwise to the list filtered to the item's type. Switching academies opens the target academy's list without filters.

## UI

`components/page.tsx` composes the toolbar (type selector in the site header, search, the audience filters (Audience type; Level always; Track for program-wide when the level has tracks; Group for group-wide, within the level; a wider change clears the narrower ones) and View options in one button group, and Create assessment). `view-options.tsx` is one popover for the Table/Cards switch, Group by (none, type, status), Order, and status toggles in two modes: All types (one toggle per status word that switches it for every listed type; partly shown is `aria-pressed="mixed"`) or Per type (each type's own statuses). Grouping by status locks All types; with one type selected only that type's section shows. Hidden toggles are muted and struck through; double-click shows only that status and the next click restores the earlier selection, as in student courses), with Reset. `groups.tsx` splits a page into its consecutive groups and labels them ("Quizzes", or a status word such as "Closed"); both views show group headings that collapse their group; collapsed groups are page state shared by both views (cards use the shadcn Collapsible, the table hides the group's rows). The page also renders loading, error and empty states and paging with the result range, total and per-page selector in both views. Page-size changes reset to page 1 and are part of the list query key and RPC limit/offset. `table.tsx` (borderless, fixed-height rows; Title with the muted audience beneath, Type, Parts, Status, Date, Marked, Actions) and `cards.tsx` render the same rows; `facts.tsx` holds the type icons, the audience line (program-wide or group-wide icon with a delayed tooltip), the marked/audience count, the type-specific status badge and the date: a short academy-time label from `formatAcademyRelative` ("Due Friday 10pm", "Closes Tonight 11pm", "Opens Next Monday 9am"; quizzes/exams show the next window event, or when it closed) with the full dates ("Fri, 30 Oct 2026 at 10:00 pm") in a delayed tooltip and for screen readers; a dash read as "Not set" when unset. Cards lead with a large type icon (type name on a delayed hover) and show the parts: a single part's kind with its icon, or "3 parts" listing each part's title and kind on a delayed hover. Empty results replace the whole table. `create.tsx` is the Assignment / Quiz / Exam menu linking to the existing create pages; creation remains open to every staff role, as before.

Legacy `/app/assignments`, `/app/quizzes` and `/app/exams` redirect to this list with `type` set.

## Quick edit

Every row and card has a context menu (right-click, touch hold, or Shift+F10 while focused) offering Edit, Summary and Open editor; table rows also expose the same menu through an Actions button. Edit and Summary open tabs in the existing floating-sheet primitive. Archived assessments open Summary with editing disabled. The sheet loads a fresh full detail snapshot, but exposes only the name, audience, part names, assignment due date, and quiz/exam timer and availability dates. Date controls compose the shadcn Calendar and Popover with a time field, Clear and Done actions; part names use horizontal inline fields with their type below the label, following the content unit settings panel. A Questions row contains the Open editor link; Cancel and Save are the footer actions. The timer remains directly editable, with a minutes suffix and −/+ controls stepping by 30 minutes (5 with Shift), including the matching arrow-key shortcuts; button steps stay within 1–600 minutes and no native number arrows are shown. Questions, choices, answer keys, instructions, solutions, scoring and part structure remain outside the sheet; the full-editor link opens the owning type's existing form.

`details.ts` projects that snapshot into the existing draft contract, preserving hidden content and stable IDs. Each save retains the reviewed version and uses the owning module's public server action; the database still enforces live tenant authority, year, state, target/structure locks and history preservation. The UI uses the owning permission helpers: assignment text details and due date follow assignment editing permissions, quiz/exam part names lock with structure, audience and timer lock with work, and only managers can change availability. Save submits all changes together and closes the sheet after success. When availability also changes, `save_quiz_settings` / `save_exam_settings` (migration `20261029045019_assessment_settings.sql`) wrap the existing preparation and availability commands in one transaction; a failure in either rolls back the whole save. These wrappers use invoker authority and preserve the underlying role, version and lock guards. Successful saves invalidate the list and owning module's queries.

Unsaved close or full-editor navigation requires discard confirmation. Pending saves prevent closing; unconfirmed saves require an explicit reload. Conflicts keep the draft and do not silently adopt a newer version. Reload explicitly discards local edits and reads the current record. Academy changes cannot apply a late result to another academy's UI. Dates use Cairo time, reject nonexistent daylight-saving times, and preserve untouched UTC instants, including seconds and repeated-hour offsets.

`summary.tsx` loads students through the owning module only when Summary opens. It shows the score distribution for complete results, part kind/question/mark cards, and the five highest available totals with completion status. View all opens the assessment workspace. Loading, empty and retryable failure states keep the sheet usable; switching tabs preserves unsaved edits.
