# Staff Assessments list

`/app/assessments` (public `/<slug>/assessments` on the staff host) is the one staff list of assignments, quizzes and exams. Product rules: [Staff Assessments area](../../../docs/product/domains/assessments.md#staff-assessments-area). This module owns only discovery: authoring, availability, submission, marking and results stay in `assignments`, `quizzes` and `exams`, and each item opens its existing `/app/<assignments|quizzes|exams>/<id>` workspace.

## Data

`list_assessments` (migrations `20261029120000_list_assessments.sql`, `20261029130000_list_assessment_counts.sql`, `20261029140000_list_assessment_program_audience.sql`, `20261029150000_list_assessment_parts.sql`, `20261029160000_list_assessment_view_options.sql`, `20261029170000_list_assessment_status_groups.sql` and `20261029180000_list_assessment_audience_filters.sql`) is a read-only security definer RPC with the same authority as `list_quizzes`/`list_exams` and the assignments RLS policy (`is_academy_member`); other or signed-out callers get `null`, which the client treats as a failure. It returns one page of a single `UNION ALL` order, so totals and pages are correct across types:

- Filters: types (any non-empty subset), academic year (or all), title search (case-insensitive substring), audience category (`program` = program-wide, covering whole-level and level-and-track audiences; `groups`; `level` alone is still accepted), and shown statuses as `type:status` keys (`assignment:closed`, `quiz:closed`, …), so one type's status never selects another's. Any subset is allowed, including none.
- Order: optional grouping first (`type`: assignments, quizzes, exams; `status`: one group per status word across every type, in the order preparing, ready, scheduled, open, finishing, active, closed, archived; each item keeps its own type's status), then `newest` (created first, then type, then ID) or `title` (case-insensitive, then created, type, ID). Grouping happens in the database, so groups stay contiguous across pages.
- Row: type, ID, title, year, audience fields and group IDs, native status (assignment state or quiz/exam phase, never mapped onto each other), due date (assignments), scheduled window (quizzes/exams), `processing_pending` for quizzes/exams, the maximum the per-type pages show (assignment `max_score`; quiz/exam total of non-excluded questions), each part's title and kind in order (`parts`; a null assignment kind is a legacy marks-only part), and `marked_count` / `audience_count` with the workspace stat meanings: assignments count recipients with every part marked of the active required cohort plus optional eligible students; quizzes and exams count accepted work with a complete result of the currently eligible students.

`queries.ts` parses the page with a discriminated union; an unknown type or a status from another type fails the whole page instead of showing a partial list. The list query has `staleTime: 0`, so edits made in workspaces show when the list reopens. A failed refresh of the same request keeps the cached rows under a "Couldn’t refresh" alert; a failure after a filter change shows no rows.

SQL coverage: `supabase/tests/assessment_list.sql` (registered in `scripts/db-test.sh`): grants, mixed ordering, totals, paging, every filter, archived phase, title order, validation, cross-academy and signed-out denial.

## State

- URL (`params.ts`, `use-params.ts`): `type`, `q`, `audience`, `level`, `track`, `groupId`, `statuses` (comma list of type:status keys; omitted means everything but archived, empty means none), `sort=title`, `group=type|status`, `page` (one-based). Invalid values fall back to defaults; any change except paging returns to page 1; switching type keeps the other filters. There is no year filter: the list always uses the active year (every year only if none is open).
- View (`view.ts`): Table or Cards, stored per signed-in user in `localStorage` (`edra:assessments-view:<userId>`), with an in-memory fallback when storage is blocked. Without a saved choice, Cards below the shared `useIsMobile` breakpoint (768 px) and Table otherwise; the server and hydration render use Table. Resizing never writes a choice. Switching views does not touch the URL or refetch.
- Return: the list remembers its query per tab and academy (`components/shared/assessment/list/return.ts`). Workspace and form breadcrumbs, the not-found state and cancelling a new form return to that state when it covered the item's type, otherwise to the list filtered to the item's type. Switching academies opens the target academy's list without filters.

## UI

`components/page.tsx` composes the toolbar (type selector, search, the audience filter, View options and Create assessment). `view-options.tsx` is one popover for the Table/Cards switch, Group by (none, type, status), Order, and status toggles in two modes: All types (one toggle per status word that switches it for every listed type; partly shown is `aria-pressed="mixed"`) or Per type (each type's own statuses). Grouping by status locks All types; with one type selected only that type's section shows. Hidden toggles are muted and struck through; double-click shows only that status and the next click restores the earlier selection, as in student courses), with Reset. `groups.tsx` splits a page into its consecutive groups and labels them ("Quizzes", or a status word such as "Closed"); both views show group headings that collapse their group; collapsed groups are page state shared by both views (cards use the shadcn Collapsible, the table hides the group's rows). The page also renders loading, error and empty states and paging. `table.tsx` (borderless, fixed-height rows; Title with the muted audience beneath, Type, Status, Date, Marked, Maximum marks) and `cards.tsx` render the same rows; `facts.tsx` holds the type icons, the audience line (program-wide or group-wide icon with a delayed tooltip), the marked/audience count, the type-specific status badge and the date: a short academy-time label from `formatAcademyRelative` ("Due Friday 10pm", "Closes Tonight 11pm", "Opens Next Monday 9am"; quizzes/exams show the next window event, or when it closed) with the full dates ("Fri, 30 Oct 2026 at 10:00 pm") in a delayed tooltip and for screen readers; a dash read as "Not set" when unset. Cards lead with a large type icon (type name on a delayed hover) and show the parts: a single part's kind with its icon, or "3 parts" listing each part's title and kind on a delayed hover. Empty results replace the whole table. `create.tsx` is the Assignment / Quiz / Exam menu linking to the existing create pages; creation remains open to every staff role, as before.

Legacy `/app/assignments`, `/app/quizzes` and `/app/exams` redirect to this list with `type` set.
