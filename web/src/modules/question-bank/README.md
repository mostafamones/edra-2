# Question bank

The [question-bank product contract](../../../docs/product/domains/question-bank.md) is implemented: **Question bank** in the staff sidebar opens the saved-question library at `/app/$academySlug/question-bank`, and **Import PDF** in the library header opens the importer at `/app/$academySlug/question-bank/import`. Import has no sidebar entry.

## Library and collections

The library is a collection browser, a compact paginated question list and a preview of the selected question. It starts at **All questions**, then lists **Topics**, **Source documents** (with their **Source sections** beneath each document) and custom **Collections**, each with a server-side member count. Search covers prompts, choices, written model answers and printed numbers across the whole authorized library; collection filtering and pagination (24 per page) also run on the server, and a new search or collection resets to the first page. Loading, an empty library, no matches (with **Clear filters**), failure and **Retry** are separate states; empty states replace the list. Below the `lg` breakpoint the browser, list and preview are successive views with **Collections** and **Back to questions** controls; the hidden panes stay mounted, so filters, page and selection survive.

The preview shows the full prompt and choices, the confirmed answer or written model answer, visuals, the original file, page(s), printed number and section, the answer source, an optional Library unit link and every collection the question belongs to. A legacy question with no topic membership shows its stored label as **Imported topic**, without claiming it was confirmed.

A question is stored once; memberships are rows in `question_bank_memberships`, so a question can belong to any number of collections without copies. Staff create and rename Topics and Collections from the browser, and add or remove Topic/Collection memberships for one question (preview) or up to 100 selected questions (bulk bar). Removing a membership never removes the question or its source evidence, and source memberships cannot be removed. Question deletion is not part of collection management. Question collections are separate from shared academy labels and Content Library units.

Storage (`supabase/migrations/20261122100000_question_bank_collections.sql`): `question_bank_collections` holds the four kinds with a check on `kind`, a composite foreign key that only lets a section point at a source document of the same academy, unique Topic/Collection names per academy (case- and whitespace-insensitive) and unique sections per document heading and starting page. Reads use manager-only RLS. All writes go through security-definer commands that recheck manager membership: `save_question_bank_import`, `create_question_bank_collection`, `rename_question_bank_collection` and `set_question_bank_memberships`. Reads use `get_question_bank_collections`, `list_question_bank_questions` and `get_question_bank_question` (security invoker). The earlier `save_question_bank_questions` is no longer callable directly, so every save records its source memberships. Existing payloads and IDs are unchanged; existing questions appear in **All questions** immediately and gain no invented topic, document or section memberships.

Source identity: before extraction, staff choose **Source document** — a **New document** (named from the file by default, editable) or an existing library document to continue. A new document gets a generated ID once per selected PDF in the open import, reused for every page range and save batch; the filename is never the identity, so two documents with the same name stay separate. Sections are consecutive runs of the same printed heading, identified by document, heading and starting page, so a heading that returns later is a new section. Only the first run of a later page range continues an adjacent section with the same heading (its last saved page is directly before the range). Shortcut: that adjacency rule cannot tell a genuinely new same-named section that starts exactly on the next range's first page; its page evidence stays in the payload. When no section is printed, the question joins only its document.

Queries share one module API: `queries.ts` keys every read by account and academy (`["question-bank", account, academy, ...]`), plus filters and page for lists. The library and the assessment picker use the same `useBankBrowse`, list and preview. Membership changes invalidate collection counts, the affected collection's lists and the touched questions' details; a save invalidates counts and lists only. Both pages remount on academy or account change, and cached results never move between scopes.

## Import PDF

Academy Owners, Head Admins and Admins can open Question bank from the staff sidebar. The route reuses the academy membership resolved by the staff layout. An Instructor cannot open the route directly. The in-memory import is discarded when leaving the page or changing academy or account. While extraction runs, or while included questions remain unsaved, leaving the import route asks for confirmation (**Keep reviewing** / **Leave**), and the browser's unload prompt is enabled.

The page starts empty or opens a built-in mixed-language sample. Managers can select multiple question PDFs, up to 1,000 pages and 200 MB each, and work through one PDF and up to 24 consecutive pages at a time. The browser reads the page count, then renders the selected range. Gemini imports also read the immediately preceding page separately for context when starting after page 1; that page's exercises stay outside the import. **Next pages** fills the next range after a successful extraction. Save or export the current review before replacing it. The selection and draft review are lost on reload; this is not an unattended job queue. Page numbers stay relative to the original PDF.

For complete short imports, a separate answer PDF is optional (up to 24 pages and 30 MB). Partial imports do not match separate or embedded answer keys across ranges, since numbering may restart outside the selected pages. Answers printed beside a question can still be extracted. Local question extraction uses the PDF text layer and flags scanned pages for visual extraction instead of creating drafts from OCR. The separate answer-key reader can still use local OCR, which downloads public Arabic and English language data on first use. Local extraction doesn't upload documents. Answer suggestions require explicit confirmation. Only reviewed questions can be exported to JSON.

The PDF worker loads bundled JPEG 2000 and JBIG2 decoders for scanned books and resizes oversized images before display. A page whose preview renders blank is flagged locally and never sent to Gemini. Compare it against the original; if a previous import cached a blank preview, select the PDF again to render it with the current decoder.

Extraction and review stay in memory until a manager explicitly saves questions to the academy bank. The review flags are heuristic; real scanned books are still needed to measure section detection, question extraction, answer matching, and recognition of equations. A manager can use the sample to check section changes, restarted numbering, a flagged page, answer confirmation, and export before trying a real excerpt.

Printed question headings take precedence over numeric table rows. For an aligned sequence of headings with PDF coordinates, review opens an excerpt with a full-page fallback. The review flags possible continuation pages without silently merging their text. Excluded questions can be restored before export. JSON v2 embeds the source pages once per export, with each question pointing to its page and, when available, its crop. The chart or table is preserved as source imagery; it is not converted into editable data.

Regression example: the four-page formative statistics exam yielded nine candidates with the old parser. Reading the same file's text layer now yields Q1–Q4 and flags pages 3 and 4 as possible continuations. The private PDF is not part of the repository; synthetic tests reproduce the structure. This check does not establish accuracy on scanned Arabic and math books.

For a question or possible continuation with a source image, select **Crop visual**, draw a rectangle around the figure or table (or use the percentage fields), enter an image description, and attach it. A question can have more than one visual. The reviewer can adjust or remove attachments; doing so returns the question to draft. The export includes the actual cropped image and its page coordinates. Cropping does not upload the page or call a model.

Automated coverage: `parser.test.ts` covers Arabic/English question boundaries and answer matching; `import.test.tsx` covers the review, export and save payload; `library.test.tsx` covers search, filters, states, memberships and stale scopes; `leave-guard.test.tsx` covers navigation protection; `sections.test.ts` and `topics.test.ts` cover section runs and multiple topics; `../../routes/app/$academySlug/-gate.test.ts` covers the route's manager-only gate.

## Extract with Gemini

The manager-only development flow reads the PDF in the browser, then asks Gemini to extract draft exercises. Clean text layers are sent in groups of up to three adjacent pages. Scans bypass local OCR. The first pass sees the original image and records a transcript, candidate exercises, printed shared instructions, and crop coordinates. The second pass works from the transcript without resending the image; dense pages are split into groups of up to ten candidates. Edra adds shared instructions and crops from the first pass to the matching drafts. Unmatched candidates and interrupted groups flag the page for comparison. Digital pages with complex notation, figures or other layout signals use their rendered image. If Gemini flags a text page for visual inspection, the importer sends that page's image once. Printed continuations can be linked within a text group; continuations beyond the submitted group still need review.

Previous-page context supplies the preceding page's text or successful scan transcript to the extraction pass, bounded to its final 12,000 characters. A scan just outside the selected range is transcribed without drafting its exercises. Within a range, transcripts are carried forward without resending earlier images, including when the earlier drafting pass fails. Gemini may copy a shared instruction, givens or parent number only when numbering and block context establish a continuation; a new block stops inheritance. Previous-page exercises and figures are never extraction targets. Missing or damaged context remains flagged for review. **Previous page** in the source viewer lets the reviewer inspect the head. Completed-result caching includes the supplied context text; transcription caching remains independent. Manager authorization applies to every request, including context-only scans and cached text.

Live regression (2026-11-18): an Arabic page-21 transcription supplied to page-22 drafting restored the shared instruction to top-of-page items 12–14, preserved the different instruction for block 3, and returned 13 page-22 exercises without importing page-21 exercises. Provider retries were needed; this verifies the context path, not every OCR coefficient. One preceding page is bounded context, so a head spanning several earlier pages can still require manual correction.

Vision results can include figure, table, diagram or given-code coordinates. The model uses Gemini's native normalized `box_2d: [top, left, bottom, right]` format; Edra converts this once into named browser bounds, validates the coordinates, and crops the original pixels without automatic padding. Blank crops and crops with scattered ink intersecting an edge are withheld with actionable feedback to crop the full figure manually. This conservative pixel check does not prove semantic correctness and may require manual correction of a tightly bounded legitimate figure. Shared visuals can appear on multiple questions. Staff can adjust or remove attachments before export. The importer discards standalone page and mark counts that the model returns as questions; a full question about pages or marks is preserved.

Math is stored as editable LaTeX inside `\(...\)` or `\[...\]`. Prompts, choices and written model answers preserve fractions, roots, powers, Arabic variables, and the printed equation order. Math fields open formatted, with **Edit source** and **Done** controls. Recognized bare TeX commands receive delimiters; equivalent repeated shared instructions and matching parenthesized question labels are removed from imported prompts. The saved bank and shared assessment displays render the same source through KaTeX's MathML output, using native browser equations with isolated left-to-right math spans inside Arabic prose. Untrusted HTML/URL commands are disabled, expansion and equation size are bounded, and invalid source stays visible with actionable validation. A question with invalid mathematical notation cannot be marked reviewed. Plain slashes, currency and code are not guessed into equations. Existing drafts normalize when opened and reviewed; stored questions are not rewritten automatically.

Within an open import, Edra keeps up to 128 complete scan results and 128 successful transcriptions per selected file. A draft timeout can return its successful transcription, so the next retry sends the bounded text instead of the image. Every request, including cached transcription requests, rechecks academy manager authority. The route remounts on academy/account changes; the file cache lives only in that route and clears on leaving or reloading. It is not a shared server cache or durable book store. Damaged math transcriptions are not cached. Source scans render at 200 dpi, capped at 2400 pixels on the long side; retries preserve that geometry and no longer use a smaller scan-specific JPEG budget.

Gemini can suggest a choice visibly marked in the PDF and transcribe a printed written solution into the separate, editable **Model answer** field. The model is instructed to use the source rather than solve the exercise. Staff confirm MCQ suggestions explicitly; marking a written question reviewed includes review of its model answer. Reviewed exports and saved questions preserve the optional written answer separately from the prompt and question visuals. The optional separate answer key stays local, and disagreements between a marked choice and a matched key are flagged. Saving a bank question does not automatically add it to an assessment.

For readable PDFs, the browser also checks the rendered pixels of labeled four-choice groups for yellow highlights. It uses this evidence only when all four options match one unique group on the page, including superscript digits in math. Multiple marked choices or a conflict with Gemini are flagged for manual review. This check uses no extra model request. Scans still rely on Gemini for visible marks.

The first button opens a confirmation before sending page images or text to Google. Use approved test material with the [Gemini Free Tier](https://ai.google.dev/gemini-api/docs/pricing). Production builds disable the action and reject its server request. Failed pages are listed in **Check**, even when no pages could be extracted. Valid exercises survive malformed neighboring entries, and their source page is flagged for comparison. When an image is unusable or the image response is invalid, the importer can retry the page with readable embedded text and flags any recovered drafts for figure and layout review. A quota response stops the remaining calls. Within the open review, retry one failed page or all failed pages without resending completed pages or discarding their edits. Only draft output is produced; extraction does not write to the academy database.

Set the server-only `GEMINI_API_KEY` in the ignored `web/.env.local`. Owners, Head Admins and Admins can run extraction on the development app using that key. Restart the development app from VS Code if the Worker has not loaded a newly configured key. The previously applied academy credential migration is retained for migration history; the app no longer reads or writes that table.

Verification: the import tests cover confirmation before transmission, page routing, a quota stop, manager authorization, and a cropped figure appearing on an unreviewed draft. A live test in the same Worker runtime as Edra also separated an exercise from a worked example and located a chart. It reproduced and verified the fix for a Worker request failure: use manual redirects and reject redirect responses so the key is never forwarded. Subsequent browser imports and remaining accuracy limits are recorded below.

### Recovery and live trial evidence (2026-11-17)

Scan drafts retry omitted or malformed candidate exercises once, in groups of at most ten, within a bounded recovery window. Recovery accepts only valid requested candidate IDs, retains successful drafts in source order, and stops after quota or credential rejection. Unresolved omissions remain page issues. A recovered batch's temporary failure note clears once all candidates are present; independent source-review notes remain. Initial scan/draft calls allow 30 seconds and their fallback allows 40 seconds; direct image recovery allows 40 seconds. Temporary failures can use the alternate Flash-Lite model. These are per-call deadlines, not an overall import deadline.

The November 17 implementation carried proposed equation crops alongside scan labels. That behavior was replaced by structured math on November 18, as described below. A complete draft label is retained when transcription provides only its child label. Invalid figure proposals are discarded and flagged without discarding a legible exercise. Extraction instructions explicitly cover lettered continuation items, shared variable/set definitions, parent numbering, and exclusion of QR codes and decorative marks. Image requests for readable PDFs also include their bounded text layer so the model can check visible continuation items against both representations; scans do not include unreliable OCR text. Source crops remain proposals that staff must inspect.

Repeated live trials covered 16 distinct pages: five Arabic textbook scans, four programming model-answer exam pages, two propositional-logic pages, two sets/functions pages, and three Arabic front-matter pages. Visual checks found and prompted fixes for missing continuation items and shared definitions: the logic continuation page changed from ten extracted items to all fourteen, with the four items missing their previous-page instruction flagged individually. The reported Arabic practice page returned all seventeen items, including its first six-item group. Cover, contents, and syllabus pages returned no questions. Exam retries retained parent labels and separated printed solutions from student prompts.

These trials do not establish perfect extraction. Google returned intermittent HTTP 503 responses and some calls timed out. Arabic coefficient, sign, equation-order and crop errors were observed, including in responses with a complete question count. The browser's five-page import recovered 44 drafts without replacing completed pages and retained one warning for four possible omissions. A subsequent individual extraction of that incomplete page returned all thirteen exercises. Continue comparing scan drafts with the original; none of these trials automatically reviewed or saved questions. The opt-in `EDRA_GEMINI_CONTINUATION_IMAGE` test takes the inspected logic continuation page image and a sibling `.txt` file with its PDF text layer. It asserts all fourteen items, missing-context checks and supplied definitions. It passed twice with image-plus-text input; earlier image-only repetitions exposed the omission, and provider failures can prevent a run from reaching its assertions.

### TeacherGen alignment (2026-11-18)

Source reviewed: the owner's `D:/teachergen-main.zip` and `D:/teachergen-feat-teacher-doc-automation.zip`, specifically `teachergen/ingest.py`, `extract.py`, `gemini.py`, `render.py` and `omml.py`. Acceptance: fractions, square/indexed roots, powers, multiplication and division render mathematically among Arabic text; LaTeX remains editable and survives bank/assessment copies; damaged notation cannot be reviewed; code and ordinary text stay literal; successful scan transcription survives drafting failure; cached text cannot bypass manager authorization; figure bounds preserve the native y/x order, with blank or potentially clipped attachments withheld. Native MathML was rendered and visually inspected in headless Microsoft Edge without horizontal overflow. Component coverage checks the actual importer preview and correction flow, shared assessment displays, unsafe input, scan caching, authorization and crop feedback.

Fraction layout uses normal MathML sizing and visible equation spans; overflow belongs to the full prompt surface rather than individual equations. The question-14 regression was checked in headless Edge using the built application CSS at 740px and 360px, with no equation scroll arrows or page overflow. Matching `14)` labels are removed even when included inside an equation delimiter. These fixture checks do not replace review in the owner's running application.

### Extended math checks (2026-11-19)

`src/lib/math.fixtures.ts` supplies 42 expressions covering square/indexed/nested roots, nested fractions, Arabic/Persian digits, powers, subscripts, quadratic formulas, inequalities, trigonometry, calculus, matrices and aligned systems. It verifies MathML, vertical bounds, default source visibility, equation scroll containers, page overflow and reachable horizontal scrolling; artifacts go to the system temporary directory under `edra-math-layout`. The expanded check found and fixed inaccessible leftward overflow in Arabic prose: the preview and rendered text now use the same explicit prose direction, while equations remain isolated left to right. Wide display equations use their natural width within the prompt's scrolling surface.

Opt-in live OCR: after the layout check, run `node --env-file=.env.local scripts/math-scan.mjs`. It generates a known 12-item math sheet and uses the actual scan/draft adapter, comparing MathML structure, variable names and ordered terms after normalizing digit shapes and whitespace. It exits unsuccessfully on differences and writes the source image, provider replies and comparison report into the same temporary directory. `MATH_SCAN_MODEL` optionally selects a scan model for a comparison; it does not change application configuration. The 2026-11-19 default pipeline run returned all 12 items, with 9 matching structures, one equivalent polynomial reorder, one reversed subtraction and one damaged nested fraction. Errors originated in transcription. A stronger `gemini-3.5-flash` comparison returned HTTP 503 on all attempts, so no accuracy conclusion or model change followed. Rendering checks pass; OCR fidelity still requires source review.

Live runs on the owner's scanned practice pages returned all seventeen and thirteen questions with delimited math and no equation-image attachments. An additional full-Flash transcription run returned thirteen questions but still misread a coefficient; no blanket model upgrade is justified by this small trial. ## Use saved questions in an assessment

In an editable exam or quiz part, academy managers can choose **Add from Question Bank**, open a saved question, and add an editable copy to the part. Use a Question Sheet for choice questions and Written Work for written questions. The copy starts at one mark and retains any confirmed key, written model answer and figures; a missing key stays unset. The assessment’s existing editor and save rules apply. Assignment authoring does not offer this action. The picker searches and filters by collection with the same server reads as the library; a copy is independent of the bank, so later collection changes never alter questions already in an assessment.

## Review topics

The extraction response includes one suggested curriculum topic or no suggestion per question. The importer supplies up to 16 previously seen labels to later extraction calls to reduce label drift; topic grouping makes no additional calls. Local extraction can suggest a named printed section and leaves generic exam headings unassigned. Printed sections, labels and source pages are preserved independently.

**Review topics** shows included questions by topic; a question with several topics appears under each. Select any subset or the whole group to confirm its suggestion, **Add topic** (an existing review or library topic, or a new one) while keeping current topics, **Move questions** to another topic, **Remove topic**, or leave them unassigned. A question can hold up to 12 confirmed topics. Only confirmed topics become Topic memberships when saved; unconfirmed suggestions are not saved. **View in queue** filters the original review list to the group. A topic change does not edit the question or reset its answer review. The reviewed JSON export carries `topics` (each label and whether it was suggested or confirmed) and, for compatibility, the first as `topic`.

Verification: Edge's built-in sample confirmed moving two questions to a new topic together, then filtering the queue while keeping the original source labels. Automated coverage checks group normalization, confirmation, the filtered queue, export, and reuse of existing topic labels inside the same extraction requests.

## Save and link to Library units

Select **Save to bank** after marking questions reviewed. Pick an existing Library program (academic year, grade, and optional track), then confirm or change the proposed unit per topic. **Review topics** can split a mixed group first. The proposal uses a compact authorized catalog and local matching, preferring unique exact titles and avoiding ambiguous matches. The catalog is scoped to academy and account; it isn't sent to Gemini. Saving without links is supported.

Each save includes up to 30 questions and a 750 KB request budget, with cropped JPEG attachments and source references. Large selections can be split; full source images remain in the optional export only. A save is atomic and repeated submissions with the same draft IDs and contents are idempotent. The database checks manager membership and revalidates the academic year and destination unit before committing. Saving never updates or publishes the unit. Saving also creates or reuses the source document, its source sections and the confirmed topics, and can optionally add the questions to an existing custom **Collection**, all in the same transaction and idempotent on retry. After a save the review stays open, with **Open library** beside the confirmation; the library shows stored questions after reload, including a link to their destination unit. Creating units from the importer is a later step.

Development verification: a generated academy in Edge loaded the Scientific-track catalog, suggested an exact unit match, saved one synthetic question, and reopened its source metadata and unit link after a page reload. The generated database types for the new table and two functions were compared with the deployed schema. The disposable database suite covers permission, cross-academy isolation and atomic rejection separately from the hosted browser check.

## Compare import approaches

From `web/`, run `node scripts/question-import-eval.mjs score scripts/fixtures/question-import-pages.json scripts/fixtures/question-import-expected.json` for a local smoke run. It includes a missed question with mixed numbering that the importer should flag, and a labelled worked example that it should ignore. The fixture tests the classifier's input; it is not a benchmark of OCR.

For a real comparison, hand-label the exercises on a short excerpt first. Record physical starting page, printed question number, kind, continuation pages, and the required tables or figures. Use the expected fixture's JSON shape. Include pages that contain only explanation, worked examples, or answer keys. Keep private documents and labels outside tracked files.

Run `node scripts/question-import-eval.mjs packet <source.pdf|pages.json>` to generate two prompts. In separate fresh chats with the same model, attach the **same original page images**, in physical page order, once with the vision-only prompt and once with the hybrid prompt. Save the JSON responses separately. Then run `node scripts/question-import-eval.mjs score <source.pdf|pages.json> <expected.json> <vision.json> <hybrid.json>`. The command never calls a model or uploads a document. With a scanned PDF, provide OCR page JSON to measure the OCR-plus-rules baseline; direct PDF input reads only its text layer.

Compare misses, false positives, wrong question types, wrong continuation links, missing or extra visual proposals, and printed multiple-choice answers with their source page. In particular, check errors on pages with no parser warnings. The rules baseline can match standalone choice rows on a page starting with an explicit answer-key heading. It does not infer unlabeled key pages or attach ambiguous answers. This pass does not score equation transcription, worked solutions, or crop precision.

To run both model passes through the Gemini API, use a [Gemini API key](https://aistudio.google.com/api-keys) from a project marked Free Tier and set `GEMINI_API_KEY` in the shell (or in an untracked environment file). From `web/` on PowerShell:

```powershell
npm run eval:question-import
```

This reads `.env.local` if present and generates the synthetic PDF in memory. To generate a PDF for manual inspection or run the comparison on another approved fixture:

```powershell
$sample = Join-Path $env:TEMP ("edra-question-import-" + [guid]::NewGuid() + ".pdf")
node scripts/fixtures/make-question-import-pdf.mjs $sample
node scripts/question-import-eval.mjs gemini $sample scripts/fixtures/question-import-pdf-expected.json
```

If using an untracked environment file, add `--env-file=.env.local` immediately after `node` on the final command. The benchmark sends the named PDF to Google twice, with separate vision-only and parser-assisted prompts, and reports scores, token counts, and timings. It accepts at most 12 pages and 4 MiB and does not retry or change billing settings. The generated PDF is synthetic; use material approved for sharing with Google. The fixture includes written exercises, a worked example, a chart, a question that continues onto the next page, and an MCQ with a printed answer at the end. It does not establish performance on scans or mixed Arabic books.

On 2026-11-09, the live Gemini 3.5 Flash-Lite comparison found all four exercises in both modes, compared with three for the rules alone. Neither mode added false questions, and both linked the continuation and printed answer correctly. Both initially missed a chart shared by two exercises. After clarifying the shared-visual instruction, the parser-assisted run linked it to both exercises; the direct run still missed one link. This is one five-page smoke test. Before production, compare the routed importer with full vision on labeled scanned Arabic and math excerpts. Measure missed/false questions, notation errors, figure crop quality, and tokens per usable question. Set any confidence threshold from those results rather than relying on the model's own confidence number.
