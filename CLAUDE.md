# Claude task delegation

- Keep the main thread's selected model and reasoning effort. When using Opus, keep product decisions, architecture, implementation planning, ambiguous debugging, contradiction resolution and final review with Opus.
- When a bounded task benefits from a subagent and its result can be checked mechanically, delegate it to **Haiku 5.5**. Examples: finding files or symbols, collecting exact references, listing routes/imports, extracting existing definitions, comparing lists, checking links, and running already-selected checks and reporting their output. Use direct tools or scripts for trivial operations where delegation would add overhead.
- For these mechanical tasks, the rule and expected output are already specified: additional reasoning does not change the required result. Do not spend Opus-level reasoning or tokens redoing the collection. Request low reasoning effort for Haiku where the delegation tool supports it; keep the parent's reasoning unchanged. This does not apply to interpreting failures, deciding what behavior is correct, or designing a fix.
- Give Haiku a narrow scope, applicable repository rules, exact search/check instructions and a concise output format. Ask for file/line references or command results, including missing evidence. Do not pass the entire conversation when a short task brief is sufficient. Haiku should return ambiguities to the parent rather than invent decisions or expand the task.
- Use the live model catalog to select Haiku 5.5; in T3 Code, discover it through `orchestrator_capabilities`. The current model ID is `claude-haiku-5-5`. Use native subagent tools when they support that model; otherwise use T3 `delegate_task` with the catalog's Claude provider instance and model. Retain the task ID and manage it through task status/cancellation; do not create a separate top-level conversation for child work. If Haiku 5.5 is unavailable, report that and use direct tools rather than silently substituting an expensive model.
- The parent checks the returned evidence and owns the conclusions. Escalate to the parent when a task needs judgment; do not increase Haiku's effort to make product or architectural decisions. Batch related searches and avoid duplicate agent work.
- Delegation preserves all `AGENTS.md` boundaries, including Master-thread planning-only rules, protected files and restricted context. This authorizes routine child tasks when useful, not autonomous implementation or additional orchestration setup.
